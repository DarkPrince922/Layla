# M3 — OSINT

## Использование

1. Откройте **Настройки → Интеграции → Intelligence APIs**.
2. Добавьте ключи нужных источников. urlscan.io допускает поиск без ключа,
   но с меньшей квотой. Остальные источники требуют ключ; доступ к отдельным
   методам также зависит от тарифа провайдера.
3. Нажмите **Проверить встроенный MCP**. Это проверяет запуск процесса и список
   инструментов, не отправляет запросы провайдерам и не проверяет валидность ключа.
4. В **OSINT → Кейсы** создайте кейс типа «Домен / IP», «Человек» или «Компания».
5. Выберите источник и запустите пассивный поиск по домену/публичному IP.
   Для кейса человека или компании связанный домен/IP задаётся явно.
6. Откройте **Материалы**, **Таймлайн** или **Источники**. Результаты сохраняются
   после перезагрузки, одинаковые наблюдения не дублируются. Можно добавить
   материал вручную, указав название, наблюдение и ссылку на источник.

Поиск по имени человека/компании, maigret и координация специализированных
агентов здесь ещё не подключены. Чат OSINT остаётся отдельным общим чатом;
он пока не запускает инструменты и не получает материалы кейса автоматически.

## Источники и пассивность

| Источник | Поддержка | Используемые методы |
|---|---|---|
| Shodan | домен, публичный IP | GET /dns/domain/{domain}, GET /shodan/host/{ip} с minify=true |
| VirusTotal | домен, публичный IP | GET /api/v3/domains/{domain}, GET /api/v3/ip_addresses/{ip} |
| SecurityTrails | домен | GET /v1/domain/{hostname} |
| urlscan.io | домен, публичный IP | GET /api/v1/search/ с domain: или ip: |

Документация провайдеров:
[Shodan](https://developer.shodan.io/api),
[VirusTotal](https://docs.virustotal.com/reference/domain-info),
[SecurityTrails](https://docs.securitytrails.com/reference/get-domain-old-1),
[urlscan.io](https://urlscan.io/docs/api/).

Встроенный сервер на официальном Python MCP SDK предоставляет только четыре
инструмента чтения. Путь запроса: API кейса → MCP ClientSession → отдельный
stdio-процесс → фиксированный HTTPS endpoint провайдера. Shell-инструментов,
произвольного URL и отправки сайтов на новое сканирование в этом сервере нет.
Домен цели локально не резолвится и не запрашивается. Сторонние MCP-серверы
реестра не вызываются автоматически из пассивного поиска.

Каждый запрос получает отдельный процесс с ключом только выбранного источника
и текущего пользователя. Ключи зашифрованы Fernet; API возвращает только маску.
Ввод ключа по HTTP требует явного подтверждения. Ошибки валидации не отражают
введённые секреты. Запросы Shodan содержат ключ в query string, поэтому HTTP
журналирование в процессе источника выключено. Редиректы не выполняются.

Один запрос получает первую страницу: до 20 результатов urlscan, один отчёт
VT/SecurityTrails или одну страницу Shodan. Это не полный обход всех данных
провайдера. Ответ ограничен 512 КиБ и временем 20 секунд, MCP — 35 секундами.
При 429, ошибке ключа, сетевом сбое или таймауте в таймлайн сохраняется понятный
статус. Автоматических повторов, активных запросов или прямого резервного
канала нет. Пустой ответ не означает, что объект безопасен.

## API и хранение

- GET/POST /api/osint/cases — список (q, subject_type, limit, offset) и создание.
- GET/DELETE /api/osint/cases/{id} — сводка и удаление кейса с его материалами.
- GET/POST /api/osint/cases/{id}/artifacts — материалы и ручные наблюдения.
- GET/POST /api/osint/cases/{id}/lookups — история и запуск пассивного запроса.
- GET /api/osint/cases/{id}/sources — сгруппированные ссылки на источники.
- GET /api/integrations/intelligence — каталог и маски ключей.
- PUT/DELETE /api/integrations/intelligence/{provider} — ключ текущего оператора.
- POST /api/integrations/intelligence/test — локальная проверка MCP.

Материалы, источники и история тоже поддерживают limit/offset. Чужие кейсы
недоступны во всех маршрутах, включая запуск запроса. Все изменения кейсов,
ключей и запросы фиксируются в AuditLog. Нормализованные наблюдения и запросы
хранятся в osint_artifacts и osint_lookups; уникальный SHA-256 отпечаток
(case_id, fingerprint) защищает от повторного импорта одного наблюдения.

## Обновление с M2

Сохраните текущий LAYLA_SECRET_KEY. При стандартном запуске контейнера миграция
0003_m3 выполняется автоматически. Она создаёт таблицы OSINT и шифрует ранее
открытые значения env зарегистрированных MCP-серверов. Нужен тот же постоянный
ключ шифрования, с которым затем будет работать API.

После получения версии M3:

```bash
docker compose up -d --build layla-core layla-frontend
```

При локальной разработке: установите обновлённые зависимости core и выполните
alembic upgrade head перед запуском API. SDK MCP теперь обязателен и входит в
образ. Ручной откат к M2 не восстанавливает открытые env: зашифрованное поле
остаётся в БД для повторного обновления, а старый код увидит пустой env.

## Проверка

Backend-тесты покрывают фиксированные адреса и HTTP-методы всех четырёх API,
пассивность, некорректные цели, таймауты/429/403/редиректы, ограничение ответа,
шифрование/маскирование, изоляцию владельцев, дедупликацию и сохранение истории.
Отдельно проверены настоящий stdio MCP-процесс, Streamable HTTP с SDK и полный
путь API → MCP → HTTP-адаптер → БД с подменой только внешнего HTTP.

Миграции проверяются на чистой SQLite БД и на заполненной схеме M2. В CI также
запускаются миграции и проверка соответствия схемы на PostgreSQL 16, все тесты
backend и production-сборка frontend.

При разработке M3 локально прошли 105 backend-тестов, lint новых Python-модулей
и production-сборка frontend. В Chromium проверены создание кейса, MCP-поиск,
дедупликация, ручное добавление, история/источники, сохранение после перезагрузки,
настройка ключа с HTTP-гейтом и навигация при ширине 1440 и 390 пикселей.

Платные источники без пользовательских ключей проверяются по контрактам API
и тестовым ответам. Их доступность и квоты с реальными ключами проверяются
после настройки в установленной Layla.
