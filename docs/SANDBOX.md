# Запуск кода: песочница проекта и Piston

Агент больше не пишет код вслепую: он может установить зависимости, запустить тесты,
увидеть ошибку, исправить и запустить снова. Вы можете делать то же самое сами — во вкладке
**Код → Терминал**.

Запуск устроен из двух частей:

| | Песочница проекта (`sandbox`) | Piston (`piston`) |
|---|---|---|
| Для чего | команды в копии проекта: `pip install`, `npm install`, тесты, сборка, скрипты | компиляция и запуск отдельной программы на любом из десятков языков |
| Языки | Python 3.12, Node.js 22, gcc/g++/make, git; по желанию Go, Rust, Java | Go, Rust, Java, C#, Kotlin, Haskell, Ruby, PHP… — ставятся в настройках |
| Зависимости | да, остаются между запусками (`.venv`, `node_modules`, кеши) | нет, только стандартная библиотека |
| Сеть | только реестры пакетов, через прокси | нет |
| Инструмент агента | `run_command` | `run_code` |

## Как это работает

- **Копия проекта.** Перед каждой командой рабочая копия в песочнице догоняет проект:
  приезжают только изменённые файлы, удалённые — удаляются. Всё, что команда создаёт или
  меняет (зависимости, сборки, отредактированные файлы), остаётся в копии и в проект **не
  попадает**. Проект меняется только инструментами файлов — с диффами, подтверждениями и
  контрольными точками, как и раньше.
- **Python.** В каждой копии сразу готово окружение `.venv`, поэтому `pip install -r
  requirements.txt` работает без `--user` и `sudo`.
- **Живой вывод.** Вывод команды виден по мере выполнения — в карточке запуска в чате и в
  терминале. Модель получает начало и конец вывода (итог тестов и текст ошибки).
- **Время.** Команда останавливается по таймауту (по умолчанию 120 с, предел — 900 с).
  Фоновые процессы тоже завершаются, поэтому серверы и watch-режимы в песочнице не живут.
- **Кнопка «Запустить»** у открытого файла выбирает команду по расширению: `.py`, `.js`,
  `.ts`, `.sh`, `.c`, `.cpp` запускаются в песочнице, остальные языки — в Piston, если он
  установлен.
- **Сброс окружения** (значок ↺ в терминале) удаляет зависимости и сборки проекта в песочнице.

## Агент и режимы

| Режим | Запуск кода |
|---|---|
| Авто | агент запускает сам |
| С подтверждением | каждая команда ждёт «Запустить» / «Отклонить» / «Разрешить всё» |
| План | недоступен — план без побочных действий |
| Ревью | доступен: агент может прогнать тесты, но файлы не меняет |

Право роли — «Запуск кода в песочнице» (`code.run`). У встроенных ролей «Разработка» и
«Поиск багов» оно есть, у своих ролей включается в **Настройки → Роли**. Если сервис не
запущен, агент не видит инструментов запуска и честно говорит, что проверить код не может.
Каждый запуск пишется в аудит (`project.agent.run`, `project.run`).

## Безопасность

- **Отдельный контейнер без привилегий.** Корень только для чтения, `no-new-privileges`, из
  capabilities оставлены только нужные серверу, чтобы запускать команды от имени
  пользователя и завершать их процессы. Память, CPU и число процессов ограничены.
- **Свой uid на каждого пользователя Layla.** Копии проектов, кеши pip/npm и процессы одного
  пользователя недоступны другим.
- **Нет пути к ядру и базе.** Ядро говорит с песочницей через unix-сокет в каталоге, доступном
  только root. Сама песочница сидит во внутренней сети, где есть только её прокси.
- **Интернет — только через прокси и только к реестрам пакетов:** PyPI, npm, Go, crates.io,
  Maven. Адреса локальной сети, loopback и метаданных облака закрыты всегда.
- **Piston** изолирует каждую программу (isolate: namespaces, cgroups, без сети). Для этого
  ему нужен `privileged`. Порт наружу не открыт, API доступен только ядру по отдельной сети.

## Настройки (.env)

Переменные необязательны — без них работают значения по умолчанию.

```ini
# Дополнительные языки в песочнице (после изменения: docker compose build sandbox)
SANDBOX_WITH_GO=false
SANDBOX_WITH_RUST=false
SANDBOX_WITH_JAVA=false
# Ресурсы контейнера песочницы (общие на всех пользователей)
SANDBOX_MEMORY=4g
SANDBOX_CPUS=2
# Предел одной команды, секунд
SANDBOX_MAX_TIMEOUT=900
# Дополнительные хосты для прокси, через запятую (поддомены подходят); «*» — любые публичные
SANDBOX_ALLOW_HOSTS=
# Пределы Piston: мс и байты
PISTON_RUN_TIMEOUT=15000
PISTON_COMPILE_TIMEOUT=60000
PISTON_RUN_MEMORY_LIMIT=536870912
```

Например, чтобы `npm install` мог скачивать пакеты прямо с GitHub:
`SANDBOX_ALLOW_HOSTS=github.com,codeload.github.com,objects.githubusercontent.com`.

## Языки Piston

После первого запуска в Piston нет ни одного языка. Администратор ставит их в
**Настройки → Песочница**: поиск, «Установить»; установка идёт в фоне и видна в «В работе».
Агент сразу видит установленные языки в описании `run_code`.

## Если не работает

- Статус обоих сервисов — **Настройки → Песочница → Проверить**.
- Логи: `docker compose logs sandbox`, `docker compose logs sandbox-proxy`,
  `docker compose logs piston`.
- **Piston постоянно перезапускается.** Ему нужны cgroup v2 на хосте (современные Ubuntu,
  Debian, Fedora — по умолчанию) и режим privileged. Проверка:
  `stat -fc %T /sys/fs/cgroup` должно вывести `cgroup2fs`. Без Piston всё остальное работает;
  отключить его можно командой `docker compose stop piston`.
- **pip/npm не может скачать пакет.** Смотрите `docker compose logs sandbox-proxy`: строки
  `denied <хост>` показывают, какой хост нужно добавить в `SANDBOX_ALLOW_HOSTS`.
- **Корпоративный прокси с подменой TLS.** Инструменты песочницы берут путь к своему корневому
  сертификату из `SSL_CERT_FILE`, `PIP_CERT`, `NODE_EXTRA_CA_CERTS` (и родственных), если они
  заданы в окружении сервиса `sandbox`.
