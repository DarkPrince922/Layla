# Локальные проекты и файловый агент

В разделе **Код → Новый проект → С нуля** укажите название. Layla создаёт пустой
каталог на сервере в `LAYLA_PROJECTS_DIR` (либо в каталоге рабочего пространства).
GitHub, git init и ключ GitHub для этого не нужны. Импорт Git остаётся отдельной
вкладкой. Каталоги получают UUID, поэтому одинаковые названия не конфликтуют.

## Работа с файлами

- Откройте файл в дереве, измените текст и нажмите **Сохранить**.
- **Создать файл** принимает относительный путь, например `src/main.py`.
  Недостающие папки создаются при сохранении.
- Кнопка удаления удаляет один файл после подтверждения в интерфейсе.
- Каждое изменение возвращает настоящий unified diff. При удалении/создании
  пустого файла операция показывается даже при отсутствии строк в дифе.
- Редактор хранит SHA-256 прочитанной версии. Если файл изменили агент или другая
  вкладка, старая версия не перезаписывает новую: API отвечает `409 Conflict`.
  Черновик остаётся в редакторе; нужно перечитать файл и повторить изменение.

На широком экране доступны дерево, редактор и агент одновременно. На узком
экране и в ручном мобильном режиме они переключаются вкладками.

## Агент

Чат постоянно связан с одним проектом. При переключении проекта открывается его
собственная история. Выберите модель с поддержкой function/tool calling и задайте
задачу, например: «Создай Python-проект с README и src/main.py».

Доступны `list_files`, `read_file`, `write_file`, `edit_file`, `append_file`,
`delete_file`. Модель не может выбрать другой корневой каталог. Права выбранной
персоны проверяются сервером: `files.read` разрешает чтение и листинг;
`files.write` — запись, правку, дозапись и удаление. Без персоны доступны все
файловые инструменты. Shell, установка пакетов и запуск кода не предоставляются.

- `edit_file` заменяет точный фрагмент (`old_string` → `new_string`, уникальный
  или `replace_all`). Правка «сделай кнопку синей» — несколько строк, а не весь
  файл заново: ответ модели не упирается в предельную длину.
- `append_file` дописывает в конец. Большой новый файл модель пишет частями:
  `write_file` с первой частью, потом `append_file`.
- Если вызов всё же не влез в предельную длину ответа, это не ошибка: ход
  повторяется с просьбой писать частями (до 2 раз).

Поддерживаются потоковые вызовы OpenAI-совместимого Chat Completions API и нативного
Anthropic Messages API. Части JSON сначала собираются и проверяются целиком.
Незавершённый ответ, превышение токенов или некорректный JSON не выполняют вызов.
Ошибки файловых операций возвращаются модели, чтобы она могла исправить путь
или перечитать версию файла. Модель/шлюз должны поддерживать указанный протокол
инструментов; обычный текст с кодом сам по себе не записывается в проект.

Изменения применяются сразу. В чате показываются действия и раскрываемые дифы,
которые сохраняются после каждой завершённой операции. Ошибка следующего шага
не откатывает уже записанные файлы. История и дифы доступны после перезагрузки.
Кнопка остановки прекращает текущий запрос, сохраняя выполненные изменения.

Страховочные пределы одного запроса — 80 раундов, 400 вызовов и 50 минут. После
них, после ошибки или остановки под чатом появляется «Продолжить»: модель видит,
что успела сделать и почему ход прервался, и продолжает с того же места.

Перед первым изменением файла в ходе его исходное состояние сохраняется
(контрольная точка). У ответа агента — «Откатить к этой точке»: файлы вернутся
к виду до этого ответа, изменения его и всех следующих ответов отменятся, а модель
узнает об откате из истории.

## ZIP

**Скачать ZIP** выгружает сохранённое состояние выбранного проекта с относительными
путями; бинарные файлы и пустые каталоги поддерживаются. Несохранённый текст
редактора в архив не входит. Архив собирается во временном файле и отдаётся
порциями; временный файл закрывается по окончании передачи.

Исключаются `.git`, `node_modules`, `.venv`, `__pycache__`, `.next`, символические
и жёсткие ссылки, специальные файлы. Лимит — 100 МиБ исходных данных и 10000
элементов. Большой архив отклоняется целиком до начала скачивания.

## Границы файлового доступа

Общий файловый сервис используется API и агентом. Он запрещает абсолютные пути,
Windows-пути, `..`, обратные слеши, управляющие символы и доступ к `.git`.
Все операции открывают компоненты пути относительно дескриптора корня с
`O_NOFOLLOW`, не переходят по симлинкам и не работают с устройствами/FIFO.
Текстовый редактор принимает UTF-8 без NUL, до 1 МБ на файл. Запись атомарна;
блокировка каталога сериализует операции Layla между процессами, а SHA защищает
от устаревших изменений. Это Linux/POSIX-реализация под существующее Docker-окружение.

## API и обновление

После обновления выполните обычную миграцию `alembic upgrade head`.
Миграция `0007_code_projects` добавляет nullable `chats.project_id`; старые чаты
и проекты сохраняются, старые чаты остаются общими без файловых инструментов.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/projects` | Создать локальный проект (`name`, необязательный `workspace_id`) |
| GET | `/api/projects/{id}/files?path=.` | Список каталога |
| GET | `/api/projects/{id}/file?path=src/main.py` | Текст и `sha256` |
| PUT | `/api/projects/{id}/file` | `path`, `content`, `expected_sha256`: `null` для нового файла, SHA для редактирования |
| DELETE | `/api/projects/{id}/file?path=…&expected_sha256=…` | Удалить файл по прочитанной версии |
| GET | `/api/projects/{id}/archive` | Скачать ZIP |
| POST | `/api/chats` | `domain: "code"`, `project_id`, модель и необязательная персона |
| GET | `/api/chats?project_id=…` | История конкретного проекта |

`POST /projects` больше не принимает произвольный серверный `path`: новые
каталоги выделяет сам сервер. Существующие пути проектов сохраняются.
Файловые API и ZIP проверяют владельца рабочего пространства. Права проверяются
повторно перед каждым запросом чата. В аудит попадают операция и путь, без
содержимого файлов.

## Проверки

Тесты покрывают обход путей, ссылки и их подмену, FIFO, конфликты параллельных
редакторов, изоляцию пользователей, CRUD, ZIP, оба потоковых протокола, обрывы,
лимиты, права персоны, сохранение дифов при ошибке следующего шага и обновление
старой схемы БД. Сетевой провайдер в тестах заменён детерминированными SSE-ответами;
файловые операции и API выполняются настоящие.
