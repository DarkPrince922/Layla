# Домен Дизайн: от брифа до сайта

Раздел собран вокруг одного потока, а не двух независимых экранов.

- **Слева — бриф и чат.** «Быстрый старт по брифу» сворачивается: он нужен, чтобы
  получить первый макет без описания задачи словами. Дальше макет дорабатывается
  в чате — обычном фоновом чате домена с файловыми инструментами.
- **Справа — живое превью.** Показывает либо файлы открытого чата (агент пишет их
  в каталог чата), либо выбранную версию из брифа. Пока чат не создал HTML-страницу,
  видна последняя версия. Переключатель источника рядом с кнопками «Превью»/«Код»,
  брейкпоинты — справа.
- **Бриф и чат раскрываются по очереди**, чтобы форма не зажимала поле ввода чата.
- **История версий.** Каждая генерация по брифу — отдельная версия. Меню версий
  над превью (иконка часов) переключает источник превью; у каждой версии своя
  корзина, внизу — «Удалить все версии». Проекты, созданные из версий, остаются.

## Бриф

Настройки разложены по группам; пустое значение («Авто») оставляет решение модели.

- **Основное:** стек, тип артефакта (18 вариантов), бренд, сфера, аудитория, язык текстов.
- **Стиль:** направление (20), тон (можно несколько), тема, композиция, плотность,
  скругления, эффекты (градиенты, стекло, зерно, 3D, параллакс…).
- **Цвет и шрифты:** 12 готовых палитр с конкретными цветами, свой акцентный цвет,
  пары шрифтов Google Fonts.
- **Контент:** одна страница или несколько экранов, секции по порядку, объём текста,
  изображения, иконки.
- **Поведение и техника:** анимации, интерактивность, приоритет устройств,
  свой CSS или Tailwind, доступность WCAG AA.
- **Креативность:** «Сдержанно» (температура 0.35), «Баланс» (температура из настроек
  модели), «Смело» (0.85), «Дерзко» (1.0). Влияет и на температуру, и на указание модели.
- **«Удиви меня»** — случайный стиль (направление, палитра, шрифты, эффекты, тон).
  Что делаем и для кого — тип, бренд, сфера, секции, язык — не меняется.

Бриф запоминается в браузере и восстанавливается после перезагрузки.

## Качество макета

Генерация по брифу и дизайн-чат получают принципы качественного фронтенда: одно ясное
направление вместо «типичного ИИ-шаблона» (Inter по умолчанию, фиолетовый градиент,
ряд одинаковых карточек), выразительная пара шрифтов, цельная палитра через
CSS-переменные, осмысленная композиция и фон с глубиной, несколько продуманных анимаций,
состояния элементов и адаптивность. Размышления — коротким планом, без кода.

## Настройки модели

Генерация идёт через тот же ход модели, что и чаты (`project_agent._turn`), поэтому
действуют настройки из «Настройки → Провайдеры → модель»: длина ответа, температура,
глубина размышлений, а также автоповтор при обрыве и подстройка под модель. Всё, что
модель не принимает, запоминается так же, как в чатах.

- Длина ответа в режиме «Авто» начинается с 16384 токенов (макет — один большой ответ)
  и растёт до 65536, если не влезло. Ручной лимит — жёсткий потолок.
- Если макет не влез в предельную длину ответа, генерация продолжается с места обрыва
  (до 4 продолжений: «Макет длиннее одного ответа — модель продолжает… (часть 2)»).
  Повторно открытый блок и нахлёст срезаются. Если и этого не хватило, сохраняется то,
  что успело сгенерироваться: недописанные теги браузер закрывает сам.
- Сорвавшуюся генерацию (ошибка, остановка) можно продолжить с её черновика:
  «Продолжить с места остановки» в ходе генерации (`POST /api/designs/generate/{job_id}/resume`).
  Бриф и черновик хранятся в задаче.
- В дизайн-чате агент правит страницу точечно (`edit_file`), а не переписывает её
  целиком, поэтому правки не упираются в предельную длину ответа.

## Генерация в реальном времени

После «Сгенерировать макет» справа открывается ход генерации:

- **размышления модели** — по мере поступления (на телефоне сворачиваются, когда
  начинается код);
- **код** — пишется на глазах, с автопрокруткой;
- **превью** — пересобирается раз в ~1,2 с из недописанного документа и само
  прокручивается к последней секции. Два iframe по очереди, поэтому без мигания;
- прогресс, модель, время, объём и кнопка **«Остановить»**.

Режим «Вместе» показывает код и превью рядом (он есть и для готовых версий).
Генерация идёт в фоне: можно уйти в другой раздел или перезагрузить страницу — ход
продолжит показываться. Клик по задаче в «В работе» открывает её здесь же.

Черновик хранится в `job.result.draft` и обновляется раз в 0,5 с; `GET /api/jobs/{id}`
отдаёт его целиком, а список `GET /api/jobs` — без черновика. После сохранения версии
черновик из задачи удаляется.

## Передача в Код

Кнопка **«Открыть в Коде»** в шапке раздела:

- для версии из брифа — `POST /api/designs/{id}/project` создаёт обычный проект,
  кладёт в него файлы макета и запоминает связь. Повторное нажатие открывает тот
  же проект, а не создаёт копию;
- для файлов чата — открывает каталог этого чата как проект (он уже существует).

Дальше это обычный проект домена Код: файловое дерево, редактор, кодинг-агент,
экспорт в ZIP. Так макет развивается в полноценный сайт без ручного копирования
HTML.

## Правка по клику

Кнопка **«Правка по клику»** над превью: наведите курсор — элемент подсвечивается, клик
выбирает его, дальше пара слов, что изменить («сделай кнопку крупнее и зелёной»). Задача
уходит агенту вместе с селектором, текстом и HTML элемента; агент находит его в исходнике и
правит точечно через `edit_file`.

- **Файлы чата** — задача отправляется в текущий дизайн-чат.
- **Версия по брифу** — Лейла создаёт новый дизайн-чат с копией файлов версии
  (`POST /api/designs/{id}/chat`) и отправляет задачу туда; сама версия не меняется.

Скрипт выбора работает внутри изолированного фрейма и общается с Лейлой только сообщениями
`postMessage`; в файлы проекта он не пишется. Та же правка по клику есть в живом превью
приложения — **Код → Превью**.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/designs/generate` | фоновая генерация макета по брифу |
| `POST` | `/api/designs/generate/{job_id}/resume` | продолжить сорвавшуюся генерацию с черновика |
| `GET` | `/api/designs` | список версий (новые сверху) |
| `POST` | `/api/designs/{id}/project` | передать макет в домен Код (идемпотентно) |
| `POST` | `/api/designs/{id}/chat` | открыть версию в новом дизайн-чате (копия файлов) |
| `DELETE` | `/api/designs/{id}` | удалить версию |
| `DELETE` | `/api/designs` | удалить все версии |

Миграция `0011_design_projects` добавляет `designs.project_id` — ссылку на проект
с `ON DELETE SET NULL`: удаление проекта не удаляет макет.
