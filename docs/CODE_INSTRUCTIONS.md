# Инструкции проекта и стили ответа Code

Функции действуют только в Code: у ведущего и независимых воркеров, внутри
выбранного проекта или его worktree. Другие домены не подключают эти источники.
Миграция БД не нужна; требуется обновить Core.

## Источники и приоритет

В каждом каталоге, от корня проекта к каталогу рабочего файла:

1. `CLAUDE.md`;
2. `.claude/CLAUDE.md`;
3. Markdown из `.claude/rules` и `.layla/rules`, включая подпапки;
4. `CLAUDE.local.md`;
5. `LAYLA.md`.

Более глубокий каталог имеет приоритет. Все инструкции помечены как проектные
данные: они не расширяют права персоны, режим, область проекта или текущую
задачу пользователя. Пользовательские и managed-файлы вне проекта не читаются.
Символические и жёсткие ссылки отбрасываются обычным файловым API.

Корневые инструкции загружаются перед первым запросом модели. Вложенные — при
первом обращении к соответствующему пути. Если обнаружены новые инструкции,
вызов возвращает `retry_required` с ними: операция ещё не выполнена, модель
должна учесть правила и повторить действие. То же относится к `cwd` команд.
Инструмент `project_instructions(path="src/main.py")` позволяет получить
правила заранее. Он доступен при праве чтения файлов, включая Plan/Review.

Чтение каталога фиксирует его инструкции до конца запроса. Правки правил
применяются со следующего запроса. После смены worktree создаётся новый снимок;
проектные инструкции прежней копии не используются как текущий источник.

## Условные правила и импорты

`.claude/rules/python.md`:

```markdown
---
paths: ['src/**/*.py', 'tests/**/*.py']
---
Проверяй изменённые функции через pytest.
```

Поддерживаются `*`, `?`, классы символов, `**` как отдельный сегмент пути,
brace expansion (`{src,tests}/**/*.{py,ts}`), extglob (`**/*.@(py|ts)`) и
отрицательные шаблоны (`!src/generated/**`). `*` не пересекает `/`, а `**`
означает ноль или больше каталогов. Dotfiles учитываются. `paths` задаётся
YAML-списком или строкой с разделителем-запятой/новой строкой; запятые внутри
скобок сохраняются. Отрицания исключают пути из всего набора, повторное включение
порядком шаблонов не поддерживается. Используется wcmatch; полная тождественность
minimatch архива не заявляется. Один набор ограничен 50 шаблонами по 300 символов
и 200 вариантами раскрытия; regex имеет таймаут, общая выборка — бюджет 100 мс.

`@docs/conventions.md` включает текст относительно файла-инструкции. `..`
допустим только при разрешении в пределах проекта. Циклы и глубина от пяти уровней
не раскрываются. Текст файла кешируется один раз, но включения из разных условных
правил получают отдельные bindings и сохраняют свою область действия.
Включения в fenced/indented code,
inline code и HTML-комментариях не раскрываются. Markdown разбирается commonmark;
поддерживаются списки/цитаты, экранированный пробел в пути, fragment после `#`.
Полная совместимость с lexer архива не заявляется. Условие родителя сохраняется
и не расширяется импортируемым файлом. HTML-комментарии вне кода не передаются
как инструкции. `claudeMdExcludes`/`laylaMdExcludes` в проектных settings-файлах
исключают файлы инструкций и includes по пути относительно корня. Приоритет
settings такой же, как для стилей ниже; последнее указанное значение заменяет
предыдущее. Ошибочная конфигурация даёт предупреждение.

Лимиты: 200 файлов / 400 bindings, 60000 символов текста суммарно, 20000 на файл,
2000 просматриваемых каталогов правил, глубина их обхода 8. Повреждённый YAML,
ссылки, недоступные файлы и обрезка дают предупреждения в контексте модели.

## Стили ответа

Задайте `outputStyle` в `.layla/settings.json`:

```json
{"outputStyle": "Short"}
```

И создайте `.layla/output-styles/short.md`:

```markdown
---
name: Short
description: Короткие отчёты о работе
keep-coding-instructions: true
---
Сначала сообщай результат, затем кратко перечисляй изменения и проверки.
```

Настройки читаются от низкого приоритета к высокому:
`.claude/settings.json`, `.claude/settings.local.json`, `.layla/settings.json`,
`.layla/settings.local.json`. Стили `.layla/output-styles/*.md` заменяют
одноимённые `.claude/output-styles/*.md`; имя берётся из `name` или имени файла.
Доступны встроенные `default`, `Explanatory`, `Learning`. Модель может вызвать
`list_output_styles` для каталога и текущего выбора; инструкция стиля загружается
один раз перед запросом. Недоступный выбранный стиль явно даёт default с
предупреждением. Ограничения — 100 файлов, 12000 символов на тело стиля.

Стили меняют подачу ответа, но сохраняют базовые правила исполнения кода,
даже при `keep-coding-instructions: false`. Нет глобальных/plugin-стилей,
отдельного UI-переключателя или транспорта BriefTool. Статус подсистемы `partial`.
