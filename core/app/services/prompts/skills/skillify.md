# Layla /skillify

Создай проектный skill из повторяемого процесса текущей беседы. Используй
видимую историю и доступные заметки memory_search; не придумывай содержание
недоступной части беседы. Учитывай исправления и предпочтения пользователя.

## Выдели процесс

Определи цель, входные параметры, последовательность действий, инструменты,
результат каждого существенного шага и способ проверить итог. Отдели проверенные
действия от неудачных попыток и временных обходов. Не переноси токены, credentials,
персональные данные, случайные идентификаторы и одноразовые пути в reusable skill.

Предложи короткое slash-имя и назначение. Если неясность меняет сам процесс,
входы или критерии готовности, задай необходимые вопросы одним вызовом ask_user.
Если данных достаточно, создавай файл без дополнительного запроса разрешения.
Не проводи многораундовое интервью ради очевидных параметров.

## Создай проектный файл

По умолчанию используй .layla/skills/<имя>/SKILL.md. Имя сегмента — латиница,
цифры, дефис или подчёркивание, до 80 символов. Проверь list_skills и существующий
файл до записи. Не затирай другой процесс под тем же именем: предложи новое имя
или уточни намерение пользователя. Соблюдай project_instructions целевого пути.

Шаблон доступен через read_skill(name="skillify", file="templates/SKILL.md").
В frontmatter укажи description, при необходимости argument-hint и arguments.
Используй только поддерживаемые поля Layla. Не объявляй инструменты, которых нет
в этой среде. allowed-tools только сужает права; для каждой задачи выбери нужный
минимум, сохранив инструменты проверки и общения, если процессу они нужны.
context: fork подходит только самостоятельному заданию без уточнений по ходу;
воркер не может создавать других воркеров. Не добавляй model/effort или команды
динамического контекста без потребности самого процесса.

В теле зафиксируй условия применения, входы, шаги, проверяемые результаты,
поведение при ошибках и короткий финальный отчёт. Параметризуй меняющиеся значения
через стандартные placeholders Layla (пример есть в шаблоне). Команды, специфичные
для проекта, возьми из его реальных scripts/config/docs. Удалённую публикацию,
сообщения людям и разрушительные действия не добавляй без основания в запросе.

Создай файл через write_file/edit_file, а не shell. Если режим запрещает запись,
покажи полный предлагаемый SKILL.md и путь как черновик; не утверждай, что сохранено.

## Проверь результат

Прочитай сохранённый файл. Проверь YAML, отсутствие неизвестных execution-полей,
полноту аргументов, существование вспомогательных файлов и конкретность критериев
успеха. При необходимости сохрани небольшие примеры в том же каталоге.
Не запускай только что созданный процесс для проверки, если он имеет побочные
эффекты. Каталог фиксируется на запуск: новый skill появится со следующего запроса.
Сообщи фактический путь, назначение и пример /имя аргументы. Если файл не сохранён,
объясни причину и оставь готовый текст для продолжения.
